# 本地赛道计次裁决台

一个完全本地运行的赛道计次（lap counting）裁决工具：录入 1～3 名选手、两段合格耗时区间与至多 40 条感应记录，自动为每名选手选出最优的完整计次方案。

- 后端：Python + FastAPI（`app/`）
- 前端：原生 HTML / CSS / JavaScript，无构建步骤（`static/`）
- 裁决算法：枚举合法趟 + DAG 动态规划（`bisect` 二分前驱），含 400 组随机数据对拍测试

## 裁决规则

每趟从同一选手的感应记录中依次选取 **起点 S → 中途门 M → 终点 F** 各一条：

1. 两段耗时（M−S、F−M）都必须落在录入的**正整数闭区间**内；
2. 同一选手的不同趟**不得共用任何记录**；
3. 后一趟的起点秒数必须**严格晚于**前一趟的终点秒数（`后起点 > 前终点`）；
4. 其余读数一律舍弃，列入“未采纳记录”。

记录可以乱序录入，同一秒允许存在多条记录。

每名选手按以下优先级选择方案：

1. **完整计次数最多**；
2. 计次数相同时，**各趟用时之和最短**（每趟用时 = 终点秒数 − 起点秒数）；
3. 仍相同时，取按计次时间顺序串接的记录 ID 序列**字典序最小**者。

没有任何完整一趟时显示 **0 次**；输入非法时只报错、**不展示任何部分结果**。修改任意输入（耗时区间、选手、感应记录，含增删行与载入示例）后，页面会按当前完整输入**自动重算所有选手**，无需再点按钮；连续编辑会合并为一次重算，“⚖ 裁决 / 重新计算”按钮仍可随时手动触发。输入非法时只显示错误，改回合法值后自动恢复裁决；等待响应期间可继续编辑，只有仍适用于当前输入的响应才会更新结果或错误。每趟已采纳计次旁可做**人工复核**（未复核/通过/存疑 + 至多 200 字备注），复核不影响裁决，且仅在本次页面会话保留、刷新即清除。

## 一键启动（Docker Compose）

```bash
docker compose up --build
```

启动后浏览器访问：

- **http://localhost:8000**

停止：

```bash
docker compose down
```

## 仅用 Docker（可选）

```bash
docker build -t lap-judge .
docker run --rm -p 8000:8000 lap-judge
```

## 本地直接运行（不使用 Docker）

需要 Python 3.10+：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

访问 **http://localhost:8000** 。

## 页面用法

1. 填写两段合格耗时闭区间（正整数秒）；
2. 添加 1～3 名选手，编号必须互异；
3. 录入感应记录：唯一字符串 ID、选手编号、门（S/M/F）、非负整数秒数；全空行会自动忽略，部分填写视为非法；
4. **无需点击按钮**：修改任意输入（区间、选手、记录，增删行、“填入示例”）后，页面会立即清除旧结果并按当前完整输入自动重算所有选手，结果按选手分卡展示每趟采纳的三条记录与两段/总用时，以及该选手所有未采纳记录。连续编辑会合并为一次重算；输入非法时只显示错误，改回合法值后自动恢复结果。“⚖ 裁决 / 重新计算”按钮仍可随时手动立即重算。
5. 每趟**已采纳**计次旁提供**人工复核**：可标记“未复核 / 通过 / 存疑”并填写至多 200 字备注，默认“未复核”；标记“存疑”必须填写非空备注，否则保存失败并保持原复核内容。复核**不改变**采纳方案、计次数与用时，且**只在本次页面会话保留，刷新页面即清除**。详见下节“人工复核”。
6. “填入示例”可快速载入一份包含多趟、乱序、舍弃读数的数据（载入后自动重算，同时清掉此前复核）；“清空”会同时清除输入、结果、错误与全部复核，此前发出的请求随后返回也不会恢复它们。

## 人工复核

每趟已采纳计次旁有一个复核区：选择状态（默认“未复核”，另有“通过”“存疑”）、填写备注（至多 200 字），点“保存复核”后即时显示状态徽标与“已保存”提示。

- “存疑”必须带非空备注（纯空白不算）；状态非法、备注超长或存疑而无备注时**保存失败，控件还原并保持此前已保存的复核内容**。
- 复核纯粹是人工标注：**不改变**后端裁决、采纳方案、计次数、各段/总用时，也不会再次请求接口。
- 复核**仅存在于浏览器当前页面会话的内存中**：刷新、关闭或重新打开页面即全部清除，不会写入后端或磁盘。

**绑定方式**：复核不按趟序号或表格行号定位，而是绑定该趟的具体内容——选手编号、三条记录的 ID / 门 / 秒数，以及两段合格耗时区间（共四段边界）。

- 只要该趟仍被最新合法裁决采纳，重排记录顺序、增删与它无关的记录或手动重新计算，都会**保留**该趟复核；
- 上述任一绑定值发生改变（例如换用了另一条记录、改了某条记录的秒数或调整了耗时区间），对应复核立即**丢弃**，即使之后再改回原值也**不会恢复**；
- 最新合法裁决中**不再被采纳**的趟（方案变化导致该趟消失），其复核同样丢弃。

**编辑期与重算**：输入非法或正在等待重算（自动或手动）期间，结果与复核编辑区都会隐藏；在途返回的旧响应不会恢复复核编辑区，也不会覆盖较新的输入状态与备注。“清空”和“填入示例”会同时清掉全部复核。

## API

`POST /api/adjudicate`

```json
{
  "standards": {"smMin": 10, "smMax": 60, "mfMin": 10, "mfMax": 60},
  "runners": [{"number": 101}, {"number": 102}],
  "records": [
    {"id": "a1", "runner": 101, "gate": "S", "time": 0},
    {"id": "b1", "runner": 101, "gate": "M", "time": 12},
    {"id": "c1", "runner": 101, "gate": "F", "time": 25}
  ]
}
```

- 合法：`200 {"ok": true, "result": {...}}`
- 非法输入：`422 {"ok": false, "error": "中文原因"}`（不返回部分结果）
- 请求体不是 JSON：`400`
